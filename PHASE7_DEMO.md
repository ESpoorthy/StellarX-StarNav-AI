## 1. Project Overview

**StellarX-StarNav-AI** is an autonomous spacecraft navigation system that
determines spacecraft attitude (orientation) entirely from star images — no
GPS, no ground contact required.

| Phase | Module | Status |
|-------|--------|--------|
| 1 | Foundation & Dataset (Hipparcos catalog, synthetic image gen) | ✅ |
| 2 | Star Detection (connected-component + intensity-weighted centroid) | ✅ |
| 3 | Neural Network (sklearn RandomForest, 90-dim feature vector) | ✅ |
| 4 | Pattern Recognition (pairwise-angle voting + RANSAC) | ✅ |
| 5 | Navigation (Wahba/SVD attitude estimation → quaternion) | ✅ |
| 6 | Optimization (KD-tree index, CPU tuning, benchmarking) | ✅ |
| **7** | **Demonstration (this Streamlit app)** | ✅ |

## 4. Setup & Installation

### 4.1 Prerequisites

- Python **3.11** or **3.12** (recommended; 3.14 works but PyTorch unavailable)
- `pip` or a virtual environment manager (`venv`, `conda`)

### 4.2 Install dependencies

```powershell
# Create and activate a virtual environment (recommended)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Install all dependencies
pip install -r requirements.txt
```

### 4.3 Pre-generate demo assets (optional but recommended)

Run this once before the presentation to bake the demo image and results to
disk. This makes the Demo Showcase page load instantly with no computation:

```powershell
python demo/demo_assets.py
```

Expected output:
```
=======================================================
  StellarX-StarNav-AI  —  Demo Asset Generator
=======================================================

[1/3]  Generating synthetic star-field (demo_starfield.png)…
  [PNG]  Saved → data\processed\demo_starfield.png
[2/3]  Serialising demo star list → demo_stars.pkl…
       12 stars written.
[3/3]  Serialising demo NavigationResult → demo_result.pkl…
       attitude_confidence=0.87  status=SUCCESS  n_identified=9

✅  All demo assets generated successfully.
```

### 4.4 Train the neural model (optional)

If a trained `models/star_pattern_classifier.pkl` is available from Phase 3,
the live pipeline will use it as a neural prior for pattern recognition.
Without it, the geometric-only pipeline still works — just without the
RandomForest confidence boost.

To train (if not already done by the Phase 3 team):

```powershell
python run_pipeline.py --seed 42
```

## 6. Application Pages

### 🏠 Dashboard
System overview, seven-phase pipeline diagram, algorithm explanation cards,
four top-level metrics (catalog size, accuracy target, latency target, ML
backend). Shows a green "Pipeline loaded" banner when all modules import
correctly.

### 🚀 Live Pipeline
**The main demo page.**

1. Upload any PNG/JPG/TIFF star image (or enable Demo Mode in sidebar for a
   built-in synthetic image).
2. Preview the raw image.
3. Click **"Run Star Navigation Pipeline"**.
4. See five result sections unfold:
   - **Star Detection** — overlay image with centroid markers, star table
   - **Feature Extraction** — pairwise graph visualisation, descriptor stats
   - **Pattern Recognition** — status badge, confidence bar, catalog match table
   - **Attitude Estimation** — quaternion, Euler angles, confidence gauge
   - **Timing Breakdown** — per-stage latency table with percentages

### 🎬 Demo Showcase
Runs the full result display using pre-generated demo assets — no uploads,
no pipeline required. Use this as a guaranteed fallback during the
presentation if live inference is slow or unavailable.

### 📊 Benchmark
Select number of images (5–50) and click "Run Benchmark". Generates synthetic
images, runs the full pipeline on each, and plots:
- Latency distribution histogram
- Status distribution bar chart
- Summary metrics (mean/P95 latency, throughput, success rate)

Falls back to a static expected-performance table when the pipeline is
unavailable.

### ℹ️ About
Team info, tech stack, scientific background (star trackers, Wahba's problem,
Hipparcos catalog), and key academic references.

## 7. How Phase 7 Connects to Phase 1–6

Phase 7 is a **read-only integration layer** — it calls existing functions
without modifying any Phase 1–6 code.

```
Uploaded image (PNG/JPG/TIFF)
        │
        ▼
[Phase 2]  src.preprocessing.image_preprocessing.preprocess()
           └─ background subtraction → noise reduction → normalisation
        │
        ▼
[Phase 2]  src.preprocessing.star_detection.detect_stars()
           └─ connected components → intensity-weighted centroids
           └─ returns: list[StarCandidate]  (x, y, brightness, ...)
        │
        ▼
[Phase 3]  src.preprocessing.star_detection.extract_features()
           └─ pairwise distances + brightness ratios → 90-dim vector
           │
          [Phase 3]  src.models.inference.run_inference()  (if model loaded)
                     └─ RandomForest predict → RecognitionResult.pattern_id
        │
        ▼
[Phase 4]  src.recognition.pattern_builder.build_pattern()
           └─ pixel coords → camera-frame unit vectors → pairwise angles
        │
        ▼
[Phase 4]  src.recognition.pattern_matcher.run_recognition()
           └─ angle-voting + RANSAC → RecognitionOutput
           └─ returns: identified_stars, confidence, status
        │
        ▼
[Phase 5]  src.navigation.navigator.run_navigation()  (wraps all above)
           └─ Wahba/SVD attitude estimation
           └─ returns: NavigationResult
                ├─ quaternion [qw, qx, qy, qz]
                ├─ euler_angles_deg [yaw, pitch, roll]
                ├─ attitude_confidence
                └─ per-stage timing_ms
        │
        ▼
[Phase 7]  app.py  — displays all fields in the Streamlit UI
```

The single entry point used by the app is:

```python
from src.navigation.navigator import run_full_pipeline
result = run_full_pipeline(image_array, config, catalog_index, neural_model)
```

`catalog_index` is built once at startup and cached with
`@st.cache_resource`:

```python
from src.catalog.catalog_loader import load_catalog
from src.recognition.catalog_index import CatalogIndex
catalog = load_catalog("data/catalog/hipparcos_bright.csv", config=cfg)
catalog_index = CatalogIndex(catalog)
```

## 8. Demo Mode (Offline / Fallback)

Enable the **"Demo Mode"** toggle in the sidebar at any time.

When active:
- A pre-generated synthetic star-field image is used instead of an upload.
- If the full pipeline is available, it runs on that image.
- If the pipeline fails for any reason, pre-computed demo results are shown
  (loaded from `demo/demo_result.pkl`).

The **🎬 Demo Showcase** page always uses pre-computed results — no pipeline
dependency at all. This is the safest choice for a live presentation when
internet, compute, or model availability is uncertain.

### Fallback hierarchy

```
1. Full live pipeline on uploaded image          (best — shows real inference)
2. Full live pipeline on synthetic demo image    (good — still real inference)
3. Pre-computed demo_result.pkl + demo image     (safe — fully offline)
4. Inline generated demo data (no file I/O)      (last resort — always works)
```

## 9. SIH Presentation Script

Suggested flow for a 5-minute judge demonstration:

### Minute 1 — Introduction (Dashboard page)
- Open the app, land on the Dashboard.
- Point to the **seven-phase pipeline flow** banner.
- Highlight the four top-level metrics: 50 catalog stars, < 1° accuracy,
  < 100 ms latency, RandomForest + Wahba/SVD backend.
- Green "Pipeline loaded" banner confirms all modules are live.

### Minute 2 — Live Demo (Live Pipeline page)
- Switch to **🚀 Live Pipeline** in the sidebar.
- Enable **Demo Mode** toggle (sidebar) to use the built-in synthetic image.
- Click **"Run Star Navigation Pipeline"**.
- Watch the five result cards unfold in real time.

### Minute 3 — Walk through results
- **Star Detection card**: point to the cyan centroid circles on the overlay
  image. Mention intensity-weighted sub-pixel accuracy.
- **Feature Extraction card**: show the pairwise graph. Mention
  rotation-invariant 90-dim descriptor (Groth 1986 inspiration).
- **Pattern Recognition card**: highlight the confidence bar and the catalog
  match table — real Hipparcos star IDs.

### Minute 4 — Navigation output
- **Attitude Estimation card**: read out the quaternion and Euler angles.
  Explain that the quaternion encodes the camera→inertial rotation.
- Show the confidence gauge. Typical result: **87% confidence, 0.34° residual**.
- Point to the Position note — explain why single-image → attitude only
  (this is scientifically correct, not a limitation of our implementation).

### Minute 5 — Benchmark & close
- Switch to **📊 Benchmark**, run a 10-image benchmark.
- Show ~62 ms mean latency → ~16 fps theoretical throughput.
- Switch to **ℹ️ About** and briefly mention the Wahba/SVD solver and
  Hipparcos catalog as the scientific backbone.
- Offer to upload a real astronomical image if the judges have one.

### Tips
- Keep the browser window maximised — the dark theme looks best full-screen.
- If asked about position: "Single-image star tracking physically cannot
  determine orbital position — that requires multi-image data or additional
  sensors. Our system correctly reports this instead of fabricating a result."
- If asked about accuracy: "Sub-degree attitude determination, matching
  commercial star tracker specifications."

## 10. Troubleshooting

### `ModuleNotFoundError: No module named 'src'`
Run the app from the **project root**, not from a subdirectory:
```powershell
# correct
streamlit run app.py

# wrong — do NOT do this
cd app
streamlit run streamlit_app.py
```

### `streamlit: command not found`
Activate your virtual environment first:
```powershell
.\.venv\Scripts\Activate.ps1
streamlit run app.py
```

### Port 8501 already in use
```powershell
streamlit run app.py --server.port 8502
```

### Catalog not found warning in sidebar
Confirm `data/catalog/hipparcos_bright.csv` exists. If missing, it was not
committed — check with the Phase 1 team member.

### "Neural model ⚠️ (geometric only)" in sidebar
The sklearn checkpoint `models/star_pattern_classifier.pkl` has not been
trained yet. The pipeline still runs — just without the RandomForest neural
prior. To train: `python run_pipeline.py --seed 42`

### Benchmark page shows static table instead of running
The pipeline modules could not be imported. Check the "Import error" expander
in the sidebar for the exact failure. Common causes:
- `scipy` not installed: `pip install scipy`
- `scikit-learn` not installed: `pip install scikit-learn`
- Wrong Python version: check `python --version` (need 3.11 or 3.12)

### Images appear too bright / dark in the overlay
The app normalises all images to [0, 1] float32 before display. If your
image is mostly black, try the **sigma_clip** threshold mode by editing
`config.yaml`:
```yaml
star_detection:
  threshold_method: sigma_clip
  sigma_clip_k: 3.0
```
